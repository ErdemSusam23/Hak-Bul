2. Software Development

2. Software Development

2.1 Requirements Analysis

Hak-Bul is designed as a web-based legal information assistant for Turkish law. The main requirement is to transform a user's natural-language question into a cited, understandable, and non-advisory legal information response.

  • Accept Turkish and English legal questions from registered users and guests.
  • Retrieve relevant legislation and court-decision chunks before generating an answer.
  • Show source summaries, legal category, confidence signals, and an informational warning.
  • Support document analysis, document comparison, templates, forum activity, and admin monitoring.
2.1.1 User Requirements

The target user needs fast legal orientation without learning legal terminology or manually searching many official resources.

  • Ask a legal question in everyday language and receive a clear answer.
  • Inspect which law article or Yargitay decision supports the response.
  • Continue conversations as a guest or authenticated user and export/share history.
  • Upload PDFs for analysis, compare two legal documents, and generate common legal drafts.

2.1.2 System Requirements
07
2. Software Development

2.1.2 System Requirements

Functional System Requirements
  • Run the RAG pipeline: category detection, query rewrite, retrieval, optional rerank, source filtering, and answer generation.
  • Provide REST and SSE endpoints for standard and streaming answers.
  • Manage JWT authentication, refresh token rotation, guest sessions, roles, and profile updates.
  • Persist chat history, feedback, shared conversations, forum content, and weak retrieval queries.
  • Expose admin analytics for users, categories, feedback, and low-confidence questions.
Non-Functional System Requirements
  • Reliability: fallback to local legal corpus when Qdrant is unavailable.
  • Performance: stream generated tokens and keep the answer flow responsive for demos.
  • Security: HttpOnly cookies for refresh/guest sessions, bcrypt password hashing, and role checks.
  • Maintainability: separate routers, services, RAG modules, migrations, and frontend flow helpers.
  • Legal safety: every answer remains informational and avoids replacing professional legal advice.

2. Software Development

2.3 Architectural Design

Frontend Layer

React 19 and Vite provide the single-page user interface. Pages are organized around chat, document analysis, comparison, templates, forum, profile, and admin views.

  • Context providers manage language, theme, and authentication state.
  • API helpers centralize request behavior and token handling.
  • Flow tests protect important user journeys.
Backend and Service Layer

FastAPI exposes REST and streaming endpoints. Routers delegate business rules to services and the RAG modules, keeping responsibilities separated.

  • Routers: auth, chat, documents, templates, feedback, forum, admin.
  • Services: chat persistence, forum moderation, feedback, templates, documents, admin metrics.
  • RAG modules: categorizer, query rewriter, retriever, reranker, generator.
Data and AI Layer

PostgreSQL stores application data, Qdrant stores legal embeddings, and Groq provides LLM inference for query rewriting and answer generation.

  • PostgreSQL and Alembic manage users, tokens, chat, feedback, forum, shares, and weak queries.
  • Qdrant indexes legal chunks with multilingual embeddings.
  • Local corpus fallback keeps retrieval usable during vector DB outages.
